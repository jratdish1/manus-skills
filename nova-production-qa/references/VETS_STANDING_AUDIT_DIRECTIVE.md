================================================================================
VETS STANDING AUDIT DIRECTIVE
CHATGPT/OPENAI AUDIT EVIDENCE — MINIMUM PASSING GRADE A
================================================================================

AUTHORITY:

Direct VETS standing order.

GOVERNING RULE:

Any official ChatGPT or OpenAI audit tool may be used as audit evidence,
provided the audit is attributable, reproducible, preserved, and tied to the
exact final artifact being approved.

MINIMUM PASSING GRADE:

A

A+ is welcome but is not required unless:

- a repository protection rule explicitly requires A+;
- an existing signed governance gate explicitly requires A+;
- a mission-specific VETS order explicitly requires A+;
- a regulatory, security, or production-critical gate requires the higher
  standard.

This directive supersedes prior blanket language requiring A+ for every task.

================================================================================
1. ACCEPTABLE AUDIT TOOLS
================================================================================

Acceptable tools include official OpenAI or ChatGPT auditing paths such as:

- Codex CLI;
- ChatGPT code review;
- ChatGPT repository or pull-request audit;
- OpenAI API model used under a documented audit rubric;
- an official OpenAI coding or security review tool;
- another authenticated ChatGPT/OpenAI audit capability approved by VETS.

The report must identify the actual tool used.

Do not describe a generic model response as an audit merely because it was
generated by AI.

================================================================================
2. REQUIRED EXACT-ARTIFACT BINDING
================================================================================

Every audit must identify:

- repository;
- branch;
- base SHA;
- exact final head SHA;
- changed files;
- deployed artifact SHA or checksum where applicable;
- audit timestamp in Pacific and UTC;
- auditor tool;
- model name;
- tool or client version where available;
- audit mode;
- evidence location.

An audit on SHA A does not certify SHA B.

Any code, configuration, dependency, workflow, or executable-document change
after the audit invalidates the audit until rerun.

Documentation-only changes after an audit must still be assessed for whether
they alter operating instructions, security gates, commands, or deployment
behavior.

================================================================================
3. MINIMUM A-GRADE STANDARD
================================================================================

Grade A requires:

- no unresolved critical findings;
- no unresolved high findings;
- no known secret exposure;
- no unauthorized production mutation;
- no arbitrary shell or command-execution path unless explicitly authorized
  and securely constrained;
- required tests passing;
- required security scans passing;
- rollback documented;
- scope verified;
- material assumptions labeled;
- evidence sufficient to reproduce the decision;
- no fabricated commands, outputs, SHAs, tests, timestamps, or grades.

Medium and low findings must be:

- remediated; or
- explicitly documented with risk, compensating control, owner, and accepted
  disposition.

An unresolved medium finding affecting authentication, authorization, secrets,
payments, production integrity, arbitrary execution, or data loss blocks an A
grade unless VETS explicitly accepts it.

================================================================================
4. INDEPENDENCE AND SELF-CERTIFICATION
================================================================================

Self-certification remains prohibited.

The implementation agent may run the audit tool, but:

- the audit prompt must request independent adversarial review;
- the tool must review the resulting artifact, not merely restate the
  implementer’s claims;
- findings and complete results must be preserved;
- the implementation agent may not invent or alter the grade;
- VETS retains final approval authority.

Where practical, use a separate ChatGPT/OpenAI session or execution context from
the builder.

================================================================================
5. AUDIT EVIDENCE
================================================================================

Preserve:

- audit prompt;
- audit response;
- session or run identifier when available;
- model and tool version;
- exact SHA reviewed;
- findings;
- remediation rounds;
- final grade;
- test results;
- scan results;
- evidence checksum or immutable storage reference.

The Master Report may contain a sanitized summary, but the complete non-secret
audit evidence must remain available.

Never include:

- API keys;
- passwords;
- private keys;
- tokens;
- cookies;
- secret environment values;
- protected customer data.

================================================================================
6. TOOLS WITHOUT NATIVE LETTER GRADES
================================================================================

If the official ChatGPT/OpenAI audit tool does not produce a native letter
grade, apply the canonical VETS rubric to its findings.

The report must state:

AUDIT TOOL NATIVE GRADE:

NONE

VETS RUBRIC GRADE:

A / B / C / HOLD

Do not claim the tool itself awarded a grade when the grade was assigned using
the VETS rubric.

The rubric decision must list the evidence supporting the assigned grade.

================================================================================
7. REQUIRED REPORT LANGUAGE
================================================================================

Use:

AUDIT STATUS: PASS — GRADE A

only when the audit applies to the unchanged exact final SHA.

Otherwise use:

- AUDIT REQUIRED
- AUDIT STALE — HEAD CHANGED
- AUDIT INCOMPLETE
- FINDINGS REMAIN
- HUMAN_REVIEW_REQUIRED
- SOURCE_UNAVAILABLE

Do not use GREEN solely because tests passed.

Do not use PASS solely because an AI response sounded favorable.

================================================================================
8. GROK 4.5 MISSION APPLICATION
================================================================================

For the Grok 4.5 chatbot reconciliation and Agent OS evaluation:

- any official ChatGPT/OpenAI audit tool is acceptable;
- minimum passing grade is A;
- the audit must cover the exact final source-control head;
- the audit must review configuration, fallback handling, cost controls,
  timeouts, retries, logging, secret boundaries, and rollback;
- production deployment must match the audited artifact;
- direct host edits must be reconciled into the source of truth;
- Agent OS routing remains unapproved until VETS reviews the final evidence.

The existing T3 independent-auditor separation remains active.

Grok 4.5 may not audit and certify its own implementation.
